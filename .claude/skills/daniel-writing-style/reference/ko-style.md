## 0. 한 문장 요약

**"개념을 친절히 풀어주는 제품 전문가의 목소리."** 합쇼체로 일관되게, 도메인 용어는 한글 음차 + 영어 원어 + 약어를 함께 제시하고, 문제 제기 → 단계적 설명 → 균형 잡힌 결론 → 부드러운 안내(CTA)로 닫는다.

---

## 1. 어조와 레지스터 (Register)

- **종결 어미: 거의 100% 합쇼체(~습니다 / ~ㅂ니다).** 전 장르에서 일관됨. 전시회 후기 같은 가벼운 글에서도 해요체로 풀어지지 않고 합쇼체를 유지한다.
- **전문가–친절형(professional-warm).** 가르치되 잘난 체하지 않는다. 독자를 "고객의 입장에서", "사용자 입장에서", "서비스 사업자들은 ... 어려움을 겪게 됩니다"처럼 독자의 상황에 감정 이입하며 시작하는 경우가 많다.
- **단정 대신 절제.** 불확실한 미래는 단언하지 않는다: "주목할 필요가 있습니다", "지켜보아야 할 것 같습니다", "더 많은 시간이 필요합니다", "~리라 기대합니다".
- **균형 감각.** 장단점을 항상 같이 둔다: "편리하지만 복잡한 멀티 DRM", "비교적 저렴하고 간단하지만 ... 제거될 가능성이 있습니다", "장점이 있습니다. 하지만 ... 단점이 있습니다".
- **CTA의 경어:** "~하시기 바랍니다", "도와드립니다", "연락해 주시기 바랍니다" — 정중하지만 과하지 않다.

---

## 2. 문장 구조와 길이

- **중간~긴 문장 선호.** 짧게 끊어 쓰기보다 절을 연결해 한 문장에 맥락을 담는다.
- **즐겨 쓰는 연결 어미:** `~며`, `~고`, `~는데`, `~기 때문에`, `~에 따라`, `~으로`, `~되어`.
  - 예) "각 트랜잭션은 블록 형태로 기록되며 이전에 생성된 블록에 연결되어 블록 체인을 형성합니다."
  - 예) "별도의 솔루션 없이도 확실하게 녹화 방지가 가능합니다."
- **수동/피동 표현이 자연스럽게 섞임** — 기술 설명 맥락상 "~됩니다 / ~되어 / ~집니다 / ~어집니다"가 빈번. (예: "나누어집니다", "전달됩니다", "발급됩니다", "처리됩니다")
- 한 문단은 보통 1~3문장. 핵심 문장 뒤에 부연 한두 문장을 붙이는 리듬.

## 3. 문단·글 구성 (결론 후행 / 설명형)

전형적인 글의 뼈대:

1. **도입(문제 제기·맥락):** 시장 현황이나 독자의 고민으로 시작. 종종 통계·뉴스 인용. ("국내 넷플릭스 유료 이용자가 150만 명을 넘어서고...")
2. **이 글의 범위 선언:** "이 글에서는 ~에 대해 (자세히) 알아보겠습니다."
3. **개요(`## 개요`) → 단계적 본문:** 개념 정의 → 작동 방식 → 사례/예제 → 변형(라이브/오프라인 등) 순으로 층층이 쌓는다.
4. **결론(`## 결론` 또는 `## 마치며`):** 핵심 요약 + 절제된 전망.
5. **부드러운 안내(CTA):** 도브러너/PallyCon 제품으로 자연스럽게 연결.

> 시간 축(과거–현재–미래)이나 유형 분류(VOD–라이브–오프라인)로 본문을 나누는 것을 즐긴다. (예: "과거 - 싱글 DRM" / "현재 - 멀티 DRM" / "미래 - CMAF")

## 4. 강조와 표기 방식

- **굵게(`**...**`)** — 핵심 용어·개념의 첫 등장, 그리고 결정적 한 문장을 통째로 강조. 빈도 높음.
- **'작은따옴표'** — 개념어·신조어를 처음 소개할 때 감싼다. (예: '멀티 DRM', '탈중앙화', 'DRM 패키징', '캠버전')
- **도메인 용어 3종 세트:** 한글 음차 + 영어 원어 + 약어를 괄호로 병기하고 "이하 X" 로 약어를 도입한다.
  - 예) **'인크립티드 미디어 익스텐션'(Encrypted Media Extension, 이하 EME)**
  - 예) **월간 라이선스 발급 수(Monthly Active License, 이하 MAL)**
- **인용/주석 처리:** 출처는 "(참고 N)" 번호로 달고 글 끝에 `### 참고 자료` / `## 참고 링크` 목록으로 모은다.
- 영문 제품·표준명은 음차하지 않고 원어 그대로 둠 (PlayReady, Widevine, FairPlay, CMAF, MPEG-DASH, HLS).
- **DoveRunner 용어 표기(2026-06-12 Daniel 확정):**
  - `Agent Readiness` → **'에이전트 준비도'**(음차 '에이전트 레디니스'는 쓰지 않음). 첫 등장 시 '에이전트 준비도'(Agent Readiness)로 병기.
  - `Distributor Watermarking`, `Anti Piracy` → **영문 그대로 표기** (한글 음차 '디스트리뷰터 워터마킹/안티 파이러시'보다 영어가 자연스럽다는 판단).
  - 단, `포렌식 워터마킹`, `멀티 DRM`은 한글 표기 유지.

## 5. 어휘 선택

- **한자어 + 영어 외래어 혼용 비율이 높음.** 기술 도메인 특성상 영어 약어가 본문에 자연스럽게 박혀 있다.
- 순우리말로 풀 수 있는 부분은 풀되("나누어집니다", "쌓는다", "막을 수 있습니다"), 기술 개념은 굳이 번역하지 않는다.
- **자주 나오는 어휘·표현:** 콘텐츠, 보안, 적용하다, 제공하다, 지원하다, 처리하다, 도입하다, 제어하다, 산출하다, 보완하다, 대응하다.
- **접속·전환 표현 단골 목록:** 하지만 · 그러나 · 이에 따라 · 이를 위해 · 또한 · 이러한 · 반면에 · 특히 · 기본적으로 · 일반적으로 · 결론적으로 · 그 외에 · 즉.

## 6. 글머리 기호 / 넘버링 / 표

- **불릿·넘버링을 적극 활용.** 병렬 정보(기능 목록, 지원 플랫폼, 단계별 절차)는 거의 항상 목록으로 정리.
- 절차·순서가 있으면 번호 목록, 속성 나열이면 불릿.
- 불릿 항목은 종종 **굵은 라벨**: 한 줄 설명 형태. (예: "- **라이선스 저장(Persistent) 여부**: 오프라인 시나리오 지원을 위한...")
- **표(table)** 를 플랫폼×환경×DRM 같은 다차원 비교에 쓴다.
- **코드 블록**으로 설정 예시·계산식을 보여준다. (```c 펜스를 즐겨 씀 — 실제 C 코드가 아니라 JSON/수식이어도)
- **인용구(`>`)** 는 본문 흐름에서 살짝 벗어나는 부연·주의·예고에 사용. (예: "> 라이선스 규칙의 ... 별도의 포스팅에서 상세하게 설명할 예정입니다.")
- **Em-dash(—)는 한국어 산문에서 쓰지 않는다.** 영어 AI 텍스트에서 빈번히 쓰이는 em-dash가 번역·재작성 과정에서 그대로 넘어오는 경우가 있으나, 한국어에서는 사용하지 않는다. 대신 별도의 합쇼체 문장, 괄호(병기), 또는 `>` 인용구 부연으로 처리한다.

## 7. 시그니처 구문 (few-shot 재현용)

- 글 열기: **"이 글에서는 ~에 대해 (자세히) 알아보겠습니다."**
- 섹션 전환: **"~에 대해 알아보겠습니다." / "이제 ~에 대해 자세히 알아보겠습니다."**
- 주제 미루기: **"~에 대한 내용은 별도의 글에서 자세히 알아보도록 하겠습니다."**
- 글 닫기: **"이상으로 ~에 대해서 자세히 알아보았습니다."**
- 절제된 전망: **"앞으로 ~ 주목할 필요가 있습니다." / "~ 지켜보아야 할 것 같습니다."**
- 예시 도입: **"~을 예로 들면," / "아래와 같은 ~을 예시로 ~해보겠습니다."**
- 균형 제시: **"~ 장점이 있습니다. 하지만 ~ 단점이 있습니다."**
- CTA: **"자세히 알고 싶으시다면 [제품/문의]를 통해 ~ 요청하시기 바랍니다."**

## 9. 재현 시 체크리스트 (Do / Don't)

**Do**
- 합쇼체로 끝까지 일관되게.
- 새 용어는 '작은따옴표' + (영어 원어, 이하 약어)로 소개.
- 문제 제기로 열고, 균형 잡힌 결론으로 닫고, 부드러운 CTA로 마무리.
- 병렬 정보는 불릿/표/코드 블록으로 구조화.
- 장단점·트레이드오프를 함께 제시.
- 불확실한 전망은 절제된 표현으로.

**Don't**
- 해요체·반말로 풀어지지 않기.
- 영어 표준·제품명을 억지로 음차하지 않기.
- 과장·단정("최고의", "완벽한", "반드시 ~할 것입니다") 피하기.
- 근거 없는 미래 단언 피하기 — "~할 것 같습니다 / 주목할 필요가 있습니다"로.
- 감탄사·이모지·과한 수사 자제.
- Em-dash(—)를 한국어 본문에 쓰지 않기 — 한국어에 어울리지 않는 부호이며 AI 글쓰기 신호로 읽힌다.

## 10. 미해결/추후 정교화 포인트

- 사내 메모·슬랙·이메일 등 **비공개 짧은 글** 샘플이 없어, 격식이 낮은 짧은 커뮤니케이션 톤은 아직 미확보.
- 위 샘플은 대부분 PallyCon/도브러너 블로그용 **공개 마케팅·교육 콘텐츠**. 순수 내부 기술 문서나 제안서 톤은 추가 샘플로 보강 필요.
- 영어 프로파일(`en-style.md`)과는 **분리 유지** — 두 언어의 패턴을 섞지 않는다.
